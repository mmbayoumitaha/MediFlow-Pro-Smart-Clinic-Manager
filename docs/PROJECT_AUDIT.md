## Priorities and finding types

- **P0:** blocks execution or is an authorization boundary that must be fixed before connecting real data.
- **P1:** breaks a core clinic workflow or a stated CV requirement.
- **P2:** correctness, usability or maintenance gap that should be closed before portfolio sign-off.
- **Confirmed:** directly visible in source or reproduced by the baseline commands.
- **Verify:** a source-supported risk whose exact runtime symptom still needs a regression test after compilation is repaired.

All current clinic records are synthetic demo data. Authorization findings concern the application design; this audit has not demonstrated exposure of an existing live backend.

6. Test mobile, tablet, desktop and enlarged-text layouts; refresh nested web links and exercise browser back.
